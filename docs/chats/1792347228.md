# Bounded context and code discoverability

Date: 2026-10-18

## Context

Repository guidance had grown into an always-loaded mixture of routing,
architecture, style, testing, and workflow detail. The large source tree was
difficult to navigate without repeating broad discovery in each conversation.

## Decisions

- Keep `AGENTS.md` as a compact router and move conditional engineering detail
  to focused documents.
- Maintain a semantic source map of boundaries, entry points, reusable cores,
  and canonical workflows rather than an exhaustive file manifest.
- Bound map descriptions to 120 characters and cap total entries/lines so new
  information must replace, merge, or prune stale information.
- Surface commands proven useful in project conversations: `rg`, focused
  `sed`, Git diff inspection, CMake/CTest presets, and Cycle automation scripts.
- Keep the full style guide out of `AGENTS.md`; route production C++ work to it
  only when relevant.
- Document configured JUCE capabilities so generic framework mechanics are not
  duplicated, while keeping Amaranth product semantics authoritative.
- Mine conversation history for operational footguns: wrong targets or
  parameters, stale artifacts, permission confusion, and misleading validation.
  Treat these as workflow defects to prevent, not as abusive tool use.

## Generalized Rules

Optimize persistent agent context for routing and hard boundaries. Put detailed
workflow knowledge behind conditional links, maintain semantic indexes with a
fixed verbosity budget, and prefer on-demand symbol search over broad preloading.
