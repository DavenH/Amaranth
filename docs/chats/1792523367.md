# Expressive instrument modelling and preset explanations

Date: 2026-10-20

## Context

Discussion of tools for agent-authored Cycle 2 presets, reference matching,
and musical evaluation established goals beyond fitting individual sounds.

## Decisions

- Human editors and agents should be able to inspect authored explanations
  of a graph component's purpose and the overall preset design. The user is
  considering attached information cards with editable text or text sections
  within node editors; the broader card/editor choice remains open.
- During the first implementation review, the user rejected canvas hover
  popups duplicating the console explanation and an information badge protruding
  from the node corner. Use console hover text and a quiet information action
  contained within the node header, aligned with its existing controls.
- Console explanations must preserve authored line breaks and wrap readably.
  Use a compact preset information action consistent with node controls,
  rather than a framed text button competing with the console.
- Treat selected-cycle waveform fitting as a local tool. The user cautions
  that time-surface fits can overfit one point in expression space and often
  generalize poorly across timbral dimensions, despite useful phase alignment
  and synthetic morphs such as PWM.
- A principal goal is an elegant saxophone model spanning many expressive
  controls: attack speed, snarkiness, buzz, brightness, grit, tremolo, growl,
  and subharmonics. Many reference recordings may inform the model; a large
  database of separately resynthesized sounds with weak timbral connectivity
  does not satisfy that goal.
- Surprising, tasteful synthetic presets are a separate valuable goal.
  Successful novelty matters alongside realistic instrument modelling.

## Generalized Rules

- Judge instrument modelling across expression dimensions and their
  interactions, rather than treating fidelity to one recorded note as success.
- Prefer compact, interconnected explanations of timbre variation. Many MIDI
  control inputs provide expressive scope without making independent sample
  fits an adequate instrument model.
- Preserve room for intentional unfamiliarity when evaluating synthetic
  presets; do not reduce preset quality to reference resemblance.
- Avoid duplicate canvas help surfaces when the console already presents the
  explanation. Keep node actions within their header rather than adding outset
  badges.

## Open Questions

- Choose the annotation UI and its node, group, and preset scopes.
- Define representative reference coverage, expression trajectories, and
  criteria for taste, novelty, and modelling elegance.
