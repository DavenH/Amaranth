# Date

2026-08-09

# Context

Cycle V2 spectral Trimesh surfaces, mesh overlays, and spy views had repeatedly
drifted apart because different paths inferred or reapplied frequency mapping.

# Decisions

- Evaluate spectral Trimesh meshes at Cycle v1 `LogRegions` coordinates, retain
  the resulting linear-bin array unchanged through graph traversal, and use the
  same mapping to place or inverse-sample it during presentation.
- Reuse Cycle v1 `LogRegions` as the authoritative frequency-coordinate mapping
  for Trimesh surfaces, mesh geometry, and compact and expanded spies.
- Resolve the mapping pitch from the Modulation Triple red/key value attached
  to the upstream Voice Context, with C3 as the default.
- A lazy expanded spy may increase traversal resolution, but it must not replace
  or mutate the compact spy payload, and both views must preserve the same
  represented frequency regions.
- Guard correspondence with numerical integration tests at more than one pitch,
  supplemented by a focused preset screenshot; visual inspection alone is not
  sufficient for this invariant.

# Generalized Rules

- Carry coordinate provenance and its parameters as metadata; never infer it
  from a renderer role or node kind.
- Share one nonlinear coordinate mapping between mesh sampling, surface/mesh
  placement, and spy reconstruction; do not confuse sampling through a mapping
  with destructively transforming the transported values.
- Test visualization parity by comparing localized value regions across source,
  compact, expanded, and overlay representations.
