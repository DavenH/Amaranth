# Session Summary

Date: 2026-09-09

## Context

A first Spy attached to a spectral Trimesh side branch appeared disconnected
until a second downstream Spy was added. Once visible, its tile looked far
weaker than the downstream spectral tile.

## Decisions

- A newly authored Spy must show a valid preview immediately; another graph
  edit must never be required to populate it.
- Spy presentation describes the observed output, not the source node's
  authoring view. Use one comparable display scale for the same signal domain
  across Trimesh, operation, and other source node families.
- Preserve exact sampled values. Correct misleading colour/display mapping
  without adding hidden gain to the Spy data.
- Treat compact Trimesh previews as authoring views of stored mesh values and
  Spies as observations of processed output. Similar structure does not imply
  equal magnitude after spectral range shaping and additive normalization.

## Generalized Rules

- Test the first item in a dynamic collection before testing the second; a
  two-item assertion can hide initialization and invalidation defects.
- Keep authoring visualization semantics separate from output-observation
  semantics when the underlying data has already passed through DSP shaping.
- Topology edits must invalidate every actively observed source, including side
  branches that are not downstream of the graph's first execution node.
