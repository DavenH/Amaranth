# Session Summary

Date: 2026-09-09

## Context

Cycle V2 currently requests a routed key/velocity envelope preparation after
note-on, so the first audio can use the authored base morph. Cycle 1 instead
materializes the routed envelope synchronously before rendering the note, but
does so through allocation- and lock-capable legacy machinery.

## Decisions

- Do not prepare the note-dependent envelope on a worker and delay voice
  activation.
- Preserve Cycle 1's first-sample timing with synchronous note-on preparation.
- Make that path lock-free, preallocated, and explicitly capacity-bounded.
- Keep immutable topology/capacity planning off realtime and reject unsupported
  graphs before publication.

## Generalized Rules

- Realtime safety must not be obtained by adding scheduling-dependent MIDI
  latency when exact event-boundary behavior is required.
- Separate non-realtime plan construction from bounded realtime
  materialization when runtime controls determine the first audible sample.
- Reuse the mature DSP core through storage-neutral interfaces; do not copy its
  algorithms into a realtime compatibility implementation.

## Open Questions

- The implementation audit must determine the exact storage bounds and
  extraction points required by the mature envelope rasterization policies.
