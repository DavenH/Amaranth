# Keep refactors understandable and reviewable

Date: 2026-10-05

## Context

A gesture refactor expanded into a large storage rewrite, with excessive design
notes and updates that did not explain the product changes clearly.

## Decisions and rules

- Preserve Cycle 1 semantics; Cycle 2 copies from the existing implementation.
- Explain edits, previews, saving and undo in ordinary product terms. The user
  rejects jargon including “boundary”, “native”, “birth” and “slice”.
- Use existing undo and interaction behavior before designing replacement storage.
- Keep design notes concise. Report actual changes, remaining work and verification.
- When scope grows substantially, reassess the design and explain the growth promptly.
- Recover only the four agreed independent fixes on a new branch from master.
  Keep the old work and unfinished changes available, and restore preset edits
  without committing them.

## Fresh plan after PR #158

The user requested a concise rewritten TDD and a fresh start from the merged
master. Start with one measured Waveshaper point drag; use existing undo and
preserve Cycle 1 behavior. Do not resume the previous storage rewrite. The current
request is to rewrite the plan, not to begin implementation automatically.
