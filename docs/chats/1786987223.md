# Date

2026-08-17

# Context

Cycle V2 Guide Curves were represented as canvas nodes even though they are
shared curve resources assigned to fine-grained mesh components. Their ports
and persistent cables made shared assignments visually noisy and obscured the
authoritative cube-component semantics.

# Decisions

- Treat Guide Curves as document-level resources with typed target assignments,
  not nodes or processing edges.
- Preserve cube-component meaning; selected vertices are only an assignment UI
  convenience.
- Put Guides and Spies in peer side-by-side shelves within one bottom workspace
  dock, beginning at a user-adjustable 50/50 split.
- Keep empty shelves visible with a vacancy placeholder. Yield shelf width only
  after explicit minimization to a Blender-style vertical drawer.
- Keep the full Guide editor above the dock so downstream Spies remain visible.
- Use selector menus as the complete initial assignment workflow. Defer drag
  and drop until every component field has a clear spatial target.
- Show only temporary one-relationship tethers; do not render persistent Guide
  cables or fan-out tethers.
- Store Guide order/naming/identity and assignments as document content; keep
  dock layout and selection as application UI state.
- Directly rewrite all Cycle V2 graph resources to the new schema. Do not add a
  compatibility adapter because Cycle V2 is undeployed.
- Completion requires removal of the Guide palette item, canvas cards, ports,
  attachment edges, cables, and hidden-node ownership.

# Generalized Rules

- Model a shared authoring asset according to its ownership and target
  semantics rather than forcing it into signal-flow node topology.
- Preserve meaningful empty space and creation affordances instead of allowing
  an empty peer pane to disappear automatically.
- Do not ship a visually attractive drag gesture when it covers only the easy
  subset of domain targets; retain a complete explicit workflow until the
  spatial language is comprehensive.
- For undeployed formats, prefer a direct canonical data rewrite and deletion
  of obsolete concepts over a compatibility layer.

# Open Questions

- A future Guide drag-and-drop design must define legible drop targets for all
  six Trimesh component fields before implementation.
