# Trimesh spectral magnitude editing

Date: 2026-10-18

## Context

The expanded spectral magnitude surface switched between discrete and
vertically blended harmonic rows during a Red morph drag in `acid-stab-3`.
An earlier regression fixture used a different preset and primary axis, then
missed the reported behavior.

## Decisions

- Prefer discrete harmonic rows in spectral magnitude surfaces; blending
  adjacent harmonic rows makes the display look less accurate.
- Match the 3D spectral band widths to the 2D log-spaced harmonic bins. The
  first band should be wider than the second at the same pitch.
- Hold the same preset state and pitch when comparing a compact Trimesh
  preview with its expanded editor; their band positions and colours should
  correspond after scaling.
- Keep compact previews and expanded editors on the same discrete-row visual
  policy. A position-only node drag should reuse its cached preview image.
- Treat a visual regression as unresolved when the user still sees the same
  symptom, even if a model-state fixture passes.
- Keep PR descriptions focused on high-value behavior and review context;
  omit routine validation lists and numerical visual-check details.
- Keep Cycle 1's 0.05 first-harmonic sampling coordinate for preset compatibility.
  Remove the visible gap through default spectral-magnitude framing in both
  expanded views and the compact preview; link the expanded frequency zooms.

## Generalized Rules

Reproduce visual editing bugs with the user's actual preset and gesture.
Check rendered frames during movement and release, including any fallback
rendering path and no-delta commit behavior.
When a drag reveals a temporary appearance change, inspect both cache
invalidation and the live paint path; assert tile reuse for position-only edits.
For linked 2D and 3D spectral views, compare actual harmonic interval widths
in a rendered frame, not only whether both views use discrete colours.
