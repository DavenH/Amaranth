# Date

2026-08-02

# Context

Cycle V2 needs an onscreen keyboard and its first standalone realtime audio
device path. Preview and offline render evidence already exist but do not prove
audible interactive playback.

# Decisions

- Present the keyboard as compact floating workspace chrome, not a graph node,
  because it has no connectivity or preset semantics.
- Keep roughly one octave directly playable without expanding another UI; use
  the product's shared note-label convention rather than inventing a new one.
- UI key gestures must emit ordinary MIDI events through the same voice path as
  hardware MIDI.
- Acceptance requires a held pointer key to produce non-silent samples through
  the running standalone audio-device callback. Offline capture or a pressed
  visual state is insufficient.

# Generalized Rules

- Place global performance controls outside graph topology unless they have
  meaningful ports and serialization semantics.
- Define interactive-audio completion at the live device boundary, and keep
  preview/offline diagnostics labelled as supporting evidence.
- Do not report realtime UI-to-audio behavior complete until the complete
  gesture, voice, callback output, and release sequence is observed.

# Open Questions

- The exact visual placement may move from a canvas overlay to a dedicated
  bottom performance strip if existing status chrome conflicts during layout.
