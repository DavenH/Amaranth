# Date

2026-07-31

# Context

Cycle V2 needed a stable ownership model for Unison, Voice Context defaults,
and purpose-specific envelopes before audible voice-lane work could proceed.

# Decisions

- Keep Unison visually and structurally distinct, but connect it only as typed
  immutable configuration consumed by Voice Context; it is not a signal
  processor or `DomainContext` passthrough.
- Voice Context accepts a default Modulation Triple, a pitch envelope, and a
  Unison configuration, then shares the resolved plan with its oscillator
  branches.
- Explicit node modulation connections override Voice Context defaults for the
  corresponding axis only.
- Envelope nodes expose a clearly visible persistent purpose: control, volume,
  pitch, or scratch. Purpose determines connection semantics and polarity.
- Scratch purpose must drive every explicitly attached Trimesh traversal in
  audio and graphics; retaining an ignored topological edge is incomplete.
- Logarithmic mode must use the shared Cycle 1 DSP transform in audio, previews,
  traversal grids, and spies rather than changing only the editor background.
- Truthful visualizations update throughout slider movement, not first at
  gesture end.

# Generalized Rules

- Represent configuration relationships as typed attachments, separate from
  runtime signal buffers and processor steps.
- Put shared defaults at the context that owns their scope and make local
  override precedence explicit.
- Keep reusable, semantically recognizable authoring nodes distinct even when
  one context is their only valid consumer.
- Treat live visual feedback and final history commit as separate gesture
  phases; repaint from current transient state.

# Open Questions

- Oscillator-specific Unison overrides may be useful later, but are outside the
  first Voice Context attachment contract.
