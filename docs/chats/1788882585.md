# Session Summary

Date: 2026-09-08

## Context

The complete Cycle V1 preset library now has Cycle V2 `.cyclegraph` ports, but
successful conversion does not establish audio-processing parity. The existing
Subbass differential fixture also no longer reproduces its previously recorded
similarity thresholds on the current merged branch.

## Decisions

- Drive Cycle V1/V2 DSP parity toward byte-identical output, not only perceptual
  correlation, spectral similarity, or gain-fitted residuals.
- Establish repeat determinism within each engine before interpreting a
  cross-engine mismatch. Presets using noise are eligible only after their seed
  lifecycle is proven repeatable and equivalent.
- Build a representative preset matrix that exercises the complete graph in
  deterministic increments, beginning with simpler localization fixtures and
  extending through spectral layers, envelopes, unison, waveshaping, impulse
  response, EQ, delay, and reverb.
- Keep exact sample parity separate from end-to-end output policy differences
  such as Cycle V2's fixed output headroom, Cycle V1 master gain, and latency.
- Record every unsupported or behaviorally incomplete Cycle V2 boundary in the
  audio-parity TDD or `docs/TDD/audio-bugs.md`, with a concrete preset and render
  artifact rather than silently loosening comparison thresholds.

## Generalized Rules

- A ported preset is representation-valid, not DSP-validated, until its source
  translation and rendered output both pass their declared parity contract.
- Never use fitted gain, time alignment, filtering, or per-cycle normalization
  to claim byte parity; report those transformations only as diagnostics.
- Checked-in parity status must be reproducible on the current branch and must
  not remain “verified” after its guard fails.
