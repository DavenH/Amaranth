# Date

2026-08-03

# Context

Cycle V2 semantic input-port icons needed a stable relationship to node
previews, sockets, and preview content.

# Decisions

- Keep semantic icons input-only and outside preview content.
- Order left-side input adornments as cable, socket, icon, then node.
- Attach the icon badge directly to the node edge so it reads as a tab rather
  than a floating label.
- Do not reserve preview gutters or reduce content for icons, outputs, or plain
  colour-coded signal ports.
- Give adjacent semantic port rows visibly generous separation; use at least a
  25% increase over the initial spacing.
- Keep every row, including collapsed cable bundles, on one equal-spacing grid.
- Use a quiet monochrome palette for semantic icons; reserve colour for cases
  such as modulation bars where the colours themselves carry meaning.
- Use one continuous attached rail for multiple semantic inputs instead of
  separate tab containers, and leave generous space between icon centres.
- Represent modulation bundles as two or three plain coloured bars rather than
  literal flags.

# Generalized Rules

- Treat semantic port icons as attached node chrome, not preview content.
- Keep connection targets on the cable-facing side of descriptive badges.
- Preserve preview area when adding connection affordances outside a node.
- Integrate icon tabs with the node's surface and outline instead of presenting
  them as independent rounded tiles.
