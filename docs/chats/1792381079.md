# Explicit wave comparison sessions

Date: 2026-10-19

## Context

Previously open factory samples reappeared whenever Trimesh opened because the
shared reference library restored active cards from an old `library.json`.
A click on a displayed wave surface also reached the Trimesh mesh interactor
and crashed because the comparison view has no editable mesh.

## Decisions

- Opening Trimesh alone must not decode or display wave references. A user
  explicitly selects or imports a reference when modelling against it.
- The imported reference catalog and pitch edits persist. Active wave cards
  may remain available across preset switches within the same app session,
  but do not reopen automatically on the next launch.
- Comparison surfaces are read-only views. Their pointer path must not enter
  mesh-editing interaction; selecting a sample by clicking its surface is safe.

## Generalized rules

Keep durable resources separate from temporary workspace activation. Treat
restoring a resource into view as an explicit product choice, not a consequence
of catalog persistence. A renderer reused for preview must have an input path
appropriate to preview semantics.
