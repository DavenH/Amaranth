# Cycle comparison dock design review

Date: 2026-10-18

## Context

The sample and Spy comparison dock worked functionally, but its first visual
implementation diverged from Cycle's established controls, curve editor,
palette, and information density.

## Decisions

- Codify the application's UI and UX language in
  [Cycle UI and UX design language](../cycle-ui-ux-design.md), then review new
  work against it at production size.
- Replace the dock's generic text-button strip with Cycle's established
  command presentation. Adding a Spy is a source menu. Undo and Redo belong to
  established command access; auditioning must be scoped to the selected
  sample. Make reference import discoverable through an application-level
  entry point; investigate a wave-reference node only with clear node
  semantics.
- Keep compact comparison cards focused on surfaces. Edit the pitch envelope
  in an expanded view using the existing two-dimensional envelope editor
  language. Remove persistent bottom sublabels and the detached note slider.
- Use the navy/charcoal workspace family rather than muted green. Avoid cyan
  for generic controls and scrollbars. Show scrollbars only when needed, using
  Cycle's established appearance.
- Correct sample/Spy display mapping so the surfaces are comparably legible
  without concealing the true signal level or adding hidden Spy gain.

## Generalized rules

Start a new UI surface by inspecting the live app's relevant controls and a
production-size screenshot. Place commands according to their object and
frequency. Reuse existing rendering and interaction semantics. Audit the
occupied content, empty space, surface exposure, and every persistent label
before calling the view finished.
