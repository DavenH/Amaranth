# Date

2026-08-02

# Context

Cycle V2 spectral-layer routing needed to be explicit without turning a single
pan operation into another full-size node panel.

# Decisions

- Represent material signal-processing and routing operations explicitly on
  the node canvas instead of hiding them in an expanded source editor.
- Scale a node's canvas footprint to the amount of information it presents.
  A single pan operation should be named Pan and look like a draggable inline
  knob, while secondary parameters remain available through selection and
  inspection.
- Inline controls need conventional, spatially legible gestures: vertical drag
  on a knob changes its value, a separate visible grab region moves the graph
  element, and meaningful cardinal values snap predictably. Hit geometry must
  match the rendered shape, and hover cursors must advertise whether a region
  adjusts a value or moves the element.
- Palette icons for inline processors should depict their canvas role, including
  the cable passing through the control, rather than resemble an unrelated
  panel control.

# Generalized Rules

- Optimize the canvas for legible signal flow: explicit does not imply large.
- Use compact cable-inline controls for simple operations and reserve full node
  panels for processors whose structure or preview needs the space.
