# Sidebar authoring and icon semantics

Date: 2026-10-08

## Context

The node palette hid individual actions in category hover menus and exposed
obsolete Channel choices. Several icons conveyed generic geometry rather than
their node operation.

## Decisions

- Show individual node icons directly in a ragged grid; six FX occupy two rows.
- Remove Channel choices from this authoring palette.
- Use plain + and ×, a saturation transfer curve for Waveshaper, recognizable
  oscillator iconography for Voice Context, and meaningful wave/surface shapes
  for Unison and Mesh.
- The scratch override blocks propagation of the Voice Context's default
  scratch envelope for its connected node. Name it for that behavior; “Use Voice
  Time” obscures its purpose. This implementation calls it “Ignore Scratch”.

## Generalized Rules

Prefer direct access and semantic symbols over category-only hover navigation
and decorative cable/geometry motifs. Preserve SVG margins when rendering so
sparse symbols are not inflated to match dense diagrams.

## Follow-up: compact palette

- Keep icons at a legible size while reducing tile margins. Item names should
  appear only on hover, without changing tile positions.
- Try a restrained calligraphic F and inverse F for Fourier transforms; preserve
  the original FFT/IFFT SVGs so the diagram option remains available.

## Colour preference

Avoid cyan as the default decorative accent. Prefer canvas midnight blue or grey;
use grey for small foreground icons that need contrast against the dark canvas.
The restrained calligraphic Fourier pair was explicitly approved. The user subsequently approved browser-left / tools-right: move the unified
Curves/Presets/Patterns column left and the node palette right.

## Monochrome at rest

The whole palette should be monochrome at rest, including Mod Triple and other
semantically coloured icons. Reveal semantic hues only on hover; isolated colour
exceptions draw too much attention within the neutral family.

## Unified Nodes tab

The permanent palette consumed useful canvas width after node addition was done.
User approved folding it into a fourth Nodes tab alongside Curves/Presets/Patterns.
Treat node addition as an occasional authoring mode; retain the tab for repeated
additions and preserve click/drag behavior. Reclaim the right canvas edge. Keep
palette headings aligned with the ragged icon rows.

Once in its own Nodes tab, the palette should use the sidebar width with larger
icons and persistent labels. Compact hover-only toolbar tiles waste the space of
a dedicated browser; adapt density and labeling to the containing UI's role.

Final density adjustment: reduce the full-width cards/icons by 20%, retain labels,
and left-align the ragged rows and headings now that they live on the left.

Give palette groups more breathing room and a restrained colour identity via a
vertical bar next to each group, while retaining monochrome icons at rest.
