# Cycle 2 keyboard shortcut direction

Date: 2026-10-18

## Context

Cycle 1 shortcuts were reviewed while adding contextual morph controls and a
focused-control keyboard glyph to Cycle 2.

## Decisions

- Model the focus glyph after a compact physical keyboard: rounded outer shell,
  two rows of round keys, and a centered spacebar.
- Treat a focused morph as the complete label/slider/Axis/Link tuple. Use one
  subtle neutral outline around the tuple, remove slider-only focus framing, and
  place the keyboard glyph beyond the tuple's trailing edge.
- Keep the active morph tuple selected after pointer release and ordinary focus
  transfer. Arrow and link shortcuts resolve against that persistent editor
  selection rather than transient component focus.
- Morph letter shortcuts change the editor-local tuple selection without moving
  native child focus. Up/Down navigates visible tuples; Shift+Left/Right adjusts
  the active value by 20 percentage points. Shift+Up/Down is intentionally
  unassigned.
- Hovering the keyboard glyph should reveal its shortcut help immediately
  through JUCE's native component enter/exit path; clicking is not the
  activation gesture. Use a compact, passive `BubbleComponent` with keycap-like
  shortcut groups rather than `TooltipWindow`'s click-sensitive state machine.
  Where the OpenGL-attached peer misses an entry callback, reconcile only the
  target's hover bounds without incorporating click state.
- Reserve cyan focus color for a genuinely active focus state. Passive shortcut
  notation such as tooltip keycaps uses the neutral resting-control border.
- Judge keycap padding from visible glyph bounds. Peer icons should have equal
  apparent outer margins; multi-icon keycaps put their extra space between the
  icons rather than around the outside.
- In shortcut-reference cards, right-align shortcut groups, keep a one-em
  gutter before their descriptions, and size the card to its occupied content
  rather than preserving an unused right-side column.
- Keep `A` as the useful selection shortcut direction, covering select-all and
  clear-selection behavior once its Cycle 2 context is designed.
- Do not carry forward the `7`/`8`/`9` link aliases.
- Do not add `E` for extrude until Cycle 2 has a mature extrusion workflow.
- Leave `W` and `[`/`]` unassigned until their dependent workflows exist.

## Generalized Rules

Port shortcuts only when the operation behind them is mature and useful in the
current product. Prefer one memorable semantic key over legacy aliases, and
defer shortcuts whose visible workflow has not yet been designed.

## Open Questions

- Define whether `A` toggles all/none within the active editor, the canvas, or
  both before implementing it.
