# Cycle V2 Trimesh Vertex-Control Semantics

Date: 2026-09-09

## Context

Cycle V2 exposed internal guide-curve dimensions as though every stored field
were an applicable vertex-panel deformer target while reorganizing the
expanded Trimesh controls.

## Decisions

- Arrange vertex parameters in two columns: time/red/blue and phase/amp/curve.
- Show Guide attachment and gain controls only for phase, amp, and curve.
- Treat the internally stored time-dimension component curve as a distinct
  concept, not as a deformer attached to the visible Time property.
- Keep morph/range controls and the cube display together in the lower row.
- Remove brittle exact factory-preset count assertions; behavioral validation
  must not depend on unrelated scratch files in the content directory.

## Generalized Rules

- Do not infer UI applicability from storage shape or enum membership. Verify
  the user-facing semantic model and mature visual precedent first.
- Group controls by the concept they manipulate, and reclaim unused affordance
  space instead of displaying disabled or nonsensical controls.
- Prefer invariant-based asset tests over exact file-count assertions.
