# Date

2026-08-01

# Context

Cycle V2 preview ports had accumulated different sizes, shapes, and colours as
new Voice Context attachments were added. The compact Voice Context summary
also used abbreviations that required interpretation.

# Decisions

- Reserve semantic colour for time, spectral magnitude, and spectral phase
  signals; present other port and cable types in monochrome.
- Put a small semantic icon immediately inside the node beside an attachment
  socket. The socket remains the outermost element at the node boundary.
- Reserve a consistent interior icon gutter for ports on every preview node.
- Keep socket geometry consistent across semantics and communicate interaction
  state without resizing it.
- Limit the Voice Context preview summary to starting domain, octave, voice
  length, and glide. Keep oversampling in the expanded editor.
- Use complete musical labels and units instead of unexplained abbreviations.
- Prefer a few large, glanceable preview values over explanatory sentences;
  summary typography should match other primary labels in the same node.
- Voice Context may expose global audition controls such as preview voice
  length in its expanded editor without turning them into serialized node
  parameters; those controls must update dependent previews continuously.
- Slider affordances imply complete down-drag-up interaction, not click-only
  value placement. Keep continuous preview invalidation narrowly scoped, and
  use compact units such as `s` in detailed control readouts.
- Expanded parameter rows should use a consistent grid: names right-aligned,
  tracks equal-width, and current values left-aligned. Discrete sliders still
  need drag behavior and labelled ticks.

# Generalized Rules

- Do not make colour carry an indefinitely growing semantic vocabulary.
- Keep boundary connectors geometrically consistent; use adjacent icons for
  secondary meaning.
- Size preview nodes from a shared port/content layout contract rather than
  placing ports over a fixed node rectangle.
- Preview summaries should optimize for immediate comprehension, not maximum
  parameter density.
