# Cycle V2 Voice And Global Graph Semantics

Date: 2026-09-11

## Context

Compiler-derived `VOICE`/`GLOBAL` badges made runtime ownership visible but
added noise and did not express the intended authoring model for global effects.

## Decisions

- Present voice-local and global audio as disjoint graphs on one canvas.
- Root the global graph at a required Global Input and terminate it at Output.
- Keep Delay and Reverb global; allow Waveshaper, IR Modeller, and EQ to select
  Voice or Global processing in their controls.
- Assume voice-local processing visually. Mark only global nodes, with an icon
  and no scope labels.
- Retain cables as visible grammar errors if a mode change makes existing
  connections invalid; do not silently rewire or delete them.
- Migrate existing effects as global and place the global graph below the
  preserved voice-local layout without overlap.

## Generalized Rules

- Prefer authored graph structure and spatial grouping over exposing inferred
  runtime implementation state as repeated labels.
- Make ownership/lifecycle modes explicit durable parameters when users can
  choose them; bypass and processing ownership are independent concepts.
- A semantic mode change may reveal invalid topology, but must preserve the
  user's connections so the error is understandable and repairable.
- Preset migrations may deliberately reposition the affected subsystem while
  preserving unrelated user-authored layout and content exactly.

## Open Questions

- The production global icon should be selected through actual-size visual
  review while retaining the established code-native icon vocabulary.
