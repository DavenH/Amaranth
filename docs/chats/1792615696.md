# Compact instrument models and visible source geometry

Date: 2026-10-21

## Context

The first saxophone anchor fits matched instantaneous tone and envelopes but
sounded sterile and used dense geometry that did not explain register changes.

## Decisions

- Prefer a small reed-like trigger waveform through a shared body response,
  with meaningful dimensions, over exact harmonic poles for each sampled note.
  Dense fits are discovery evidence rather than the desired instrument design.
- For brief octave-like instability, repeat the time waveform twice, run the
  oscillator an octave lower, and temporarily perturb one copy. Fixed spectral
  comb poles on a logarithmic display do not track this relation across pitches.
- Preserve absent odd bins with multiplicative body filtering. Additive spectral
  filling defeats the doubled waveform's settled symmetry.
- Author clearly visible source geometry. Set listening level with gain rather
  than shrinking the time waveform into a nearly flat editing surface.
- Reuse factory saxophone time-domain Guide grain as a starting point; distinguish
  grain from broad spectral hiss. Investigate colored/correlated Guide noise as
  an evidence-backed feature opportunity.
- Lay out cards and cables deliberately, with no overlaps and short readable
  signal paths. Semantic simplicity includes the visible graph.
- Replace chopped cubes with simple rail Guides where motion is only one
  dimensional. Preserve full interpolation freedom only where it contributes;
  measure runtime work separately from geometry counts.
- The user accepts `reed-saxophone` as the starting architecture and likes its
  sub-octave behavior, while rejecting its initial tone as a saxophone match.
  Preserve that onset/asymmetry while trying a near-impulse or narrow-PWM
  excitation with broad harmonic support and multiplicative spectral shaping.
- Use a persistent live app connection for exploratory inspection, edits and
  auditions. Repeatedly authoring a new Python script for each trial adds
  unnecessary friction. Keep scripts for reproducible generation and validation;
  MCP is optional tooling around the app's existing semantic socket commands.
- With a single Voice Context, let sources resolve it implicitly. Add explicit
  context cables when multiple contexts require disambiguation, rather than
  repeating the default connection across the graph.
- The user rejected the refined reed preset's overall saxophone identity after
  its control/runtime checks passed. Treat this as an unmet acoustic goal.
  Spectral descriptors, working articulation and tidy geometry do not establish
  a successful reference match. Demonstrate actual settings with level-declared
  source/synth listening comparisons before describing the sound as successful.
- The user values the compact source/synth listening comparison and pointed to
  Cycle V2's wave-reference cyclograms and spectral views for diagnosis. Use
  the existing reference workflow alongside auditions to inspect attack, body
  and changing timbre; record concrete missing views in the modelling queue.

## Generalized Rules

Measure shared behavior across notes and controller trajectories early. A close
single-note fit does not establish generalization, musical utility or taste.
