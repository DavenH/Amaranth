# Context

The Voice Context design exposed a second required boundary: oscillator
subgraphs do not all execute in the same coordinate, and Unison lowering
differs when spectral processing is present.

# Decisions

- Compile maximal oscillator regions independently under one Voice Context.
- Time-only regions execute the cycle recipe separately for every Unison lane,
  matching Cycle 1 chained-cycle behavior.
- Spectral regions calculate one shared fixed cycle frame, then reconstruct,
  phase, resample, pan, and accumulate it separately for every Unison lane.
- Fold each oscillator's Unison lanes before ordinary sample-block Add or
  Multiply. This permits non-pitch-aligned oscillator AM/ring modulation.
- Select execution strategy per oscillator region; one spectral branch must not
  force sibling oscillators into spectral execution.
- Preserve Cycle 1's half-cycle crossfade as the parity reconstruction policy,
  while allowing a future genuine windowed overlap-add policy with explicit
  window, hop, tail, latency, and bin-mapping semantics.

# Generalized Rules

- Keep signal domain, execution coordinate, and runtime ownership scope as
  separate compiler concepts.
- Combine unrelated oscillators only after both are represented on the common
  sample timeline.
- Share immutable prepared products where possible, but isolate phase,
  resampling, overlap, and tail state per runtime lane.
- Treat reconstruction policy and latency as audible graph semantics, not
  hidden processor implementation details.

# Open Questions

- The future 2x overlap-add window still needs an exact time-support,
  harmonic-bin, hop, and synthesis-window contract.
