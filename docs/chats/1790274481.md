# Analytical Scalar-Surface Colour

Date: 2026-09-24

## Context

Iteration on Cycle time-domain scalar surfaces showed that attractive terrain
relief and a dark bipolar midpoint can introduce false ridges or contour-like
features into analytical signal views.

## Decisions

- Offer time-surface colour as a user-selectable View-menu preference shared by
  Cycle 1 and Cycle V2 rather than forcing one treatment on every workflow.
- Make a sequential blue-depth treatment the default while retaining the
  signed warm/cool bipolar treatment as an option.
- Keep time-domain base ramps smooth and monotonic in perceived value, with a
  balanced, low-saturation midpoint. A perfect ramp must not reveal colour
  bands, luminance reversals, or a false centre line.
- Add non-blue colour only from genuine high-pass signal detail. Use a
  restrained burgundy-to-red-to-amber accent indexed by detail strength and
  blended in linear RGB.
- Keep the spectral-magnitude palette independent. Its deliberate colour
  banding communicates amplitude regions and must not be generalized into the
  time-domain ramp.

## Generalized Rules

- In analytical signal displays, fidelity outranks dramatic topographic form.
  Broad waveform structure belongs in scalar colour, not relief-derived ridges.
- Treat base value colour and derivative accents as separate semantic channels:
  the base must remain readable without the accent, and a smooth ramp should
  produce no accent at all.
- When changing visual material policy, preserve a selectable prior treatment
  if both views remain useful, and apply the same shared material contract in
  compact previews, expanded views, GPU rendering, and CPU fallback.
