# Analytical Scalar-Surface Colour

Date: 2026-09-24

## Context

Iteration on Cycle time-domain scalar surfaces showed that attractive terrain
relief and a dark bipolar midpoint can introduce false ridges or contour-like
features into analytical signal views.

## Decisions

- Offer time-surface colour as a user-selectable View-menu preference shared by
  Cycle 1 and Cycle V2 rather than forcing one treatment on every workflow.
- Make a sequential blue-depth treatment the default while retaining the
  signed warm/cool bipolar treatment as an option.
- Keep time-domain base ramps smooth and monotonic in perceived value, with a
  balanced, low-saturation midpoint. A perfect ramp must not reveal colour
  bands, luminance reversals, or a false centre line.
- Add non-blue colour only from genuine high-pass signal detail. Use
  magenta/cyan/yellow to encode the undirected local-gradient angle while
  detail energy continuously controls blend strength. Blend in linear RGB and
  avoid lower cutoffs or multiplied threshold gates that make the accent
  appear binary.
- Keep a separate pure Blue Depth option whose output is exactly the original
  Cycle 1 `Gradients::blue_png` lookup table. It has no emboss, derivative tint,
  cavity, shadow, or specular contribution; directional detail remains an
  explicit alternative.
- Offer the bipolar palette both with high-pass detail and as a colour-only
  mode. The colour-only mode must be a strict scalar-value lookup with no
  derivative or relief contribution.
- Offer stronger illustrative lighting separately as Bipolar Shaded: quieter
  base colours, smoothly compressed directional highlights, and weaker opposing
  shade. Derive every feature from the signal; keep the colour-only modes as
  the direct amplitude reference.
- For the illustrative shaded mode, prefer copper/ice (navy troughs, steel-blue
  transitions, copper/apricot peaks). Avoid grey pearl overlays that resemble
  plastic shrink-wrap; brighten the underlying colour rather than mixing in
  a broad neutral film. This refines the shaded option, not the analytical modes.
- Broad directional illumination can still look plastic even without a pearl
  overlay. Separate broad value colour from mid/high-frequency detail; prefer
  saturated copper/gold and ice accents on real detail over illuminating entire
  waveform faces. Keep the synthetic reference aspirational, not a topology source.
- Keep the spectral-magnitude palette independent. Its deliberate colour
  banding communicates amplitude regions and must not be generalized into the
  time-domain ramp.

## Generalized Rules

- The user rejected the later copper/ice iterations as a broadening, not a
  remaining, gap. Do not label changes visual progress based on tests or a
  different signal. Use Stengah, B0, Spy 1 at impulseResponse.time as the
  reference fixture, with the app's pitch-dependent capture length. Compare
  actual before/after renders; tests establish safety, not aesthetic success.
- In analytical signal displays, fidelity outranks dramatic topographic form.
  Broad waveform structure belongs in scalar colour, not relief-derived ridges.
- Treat base value colour and derivative accents as separate semantic channels:
  the base must remain readable without the accent, and a smooth ramp should
  produce no accent at all.
- When changing visual material policy, preserve a selectable prior treatment
  if both views remain useful, and apply the same shared material contract in
  compact previews, expanded views, GPU rendering, and CPU fallback.
