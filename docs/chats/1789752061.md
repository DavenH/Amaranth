# Architecture Review Triggers

Date: 2026-09-18

## Context

A Cycle V2 quality review followed a merged causal-update extraction. The user
asked for durable, measurable prompts for future architecture review and a TDD
for concrete remaining work.

## Decisions

- Treat large source size as a review trigger, not proof that a file should be
  split. Measure responsibilities, policy decision sites, dependency direction,
  and what old code an extraction deletes.
- Keep remaining causal-update refresh migration in its existing TDD; do not
  declare it complete merely because the scheduler and renderer landed.
- Track other Cycle V2 architecture slices in a separate TDD with baseline
  sizes and observable completion evidence.

## Generalized Rules

- Run the architecture size audit during nontrivial Cycle V2 production work.
  Record why a triggered file is cohesive or plan an extraction before it grows.
- Count an architecture refactor complete only when it narrows ownership and
  removes duplicate paths; line-count reduction by itself is insufficient.
